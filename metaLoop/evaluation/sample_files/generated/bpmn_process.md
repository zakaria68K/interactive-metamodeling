The system shall manage a collection of activities representing units of work within a process. Each activity must have attributes to define its unique identity and characteristics. The system shall also support the identification of points at which a process begins; such points must be clearly distinguished and are associated with initiating the flow of activities. Correspondingly, the system shall manage points where a process concludes; these termination points must be identifiable and mark the completion of the sequence of activities.

Between these various elements, the system shall record directed connections that define the order in which activities and events occur. Each connection must specify a single source element from which the flow originates and a single target element where the flow continues. The system must ensure that these connections unambiguously represent the progression from one unit or event to the next.

A process in the system consists of at least one initiating point, one or more units of work, and at least one termination point interconnected by these directional connections, thereby creating a clear and valid progression from start to finish. Each initiating point and termination point belongs to exactly one process, while activities may be part of the same or different processes but always linked appropriately via the connections.

When defining the flow within a process, the system shall prevent cycles that do not include initiation points, ensuring logical progression. The system must allow the inspection and retrieval of the entire sequence of elements and flows to facilitate analysis and execution of the process. Furthermore, it shall support validation that every non-terminating element has at least one outgoing connection, and every non-initiating element has at least one incoming connection, preserving the integrity of the process model.
